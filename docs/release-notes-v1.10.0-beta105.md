# Cat Client v1.10.0-beta105 (versionCode 172) — تانل: حالا آدرسِ واقعی را نشان می‌دهد

این نسخه یک دروغِ نمایشی را برمی‌دارد و مسیرِ «صادق‌بودنِ» تانل را کامل می‌کند.
پنل همراه همان **6.67.1** است (تغییری ندارد).

## ۱) مشکل چه بود

وقتی یک مسیر را با IP pin می‌کردی، **سوکت واقعاً به آن IP** می‌رفت، ولی جزئیاتِ اتصال
(و نوتیفیکیشن) همان آدرسِ داخلِ اشتراک را نشان می‌داد — چون رانتایمِ زنجیره بعد از
شروع، `endpoint` را از `finalCandidate.profile` می‌ساخت. یعنی عددی که برای
«از کجا می‌روم؟» می‌دیدی با واقعیت نمی‌خواند.

## ۲) چه چیزی عوض شد

- `connectWithConnectionChain` حالا pinِ مسیرِ آخرین را resolve می‌کند:

```kotlin
val finalPin = plan.finalHop.serverOverride?.let(::connectionChainEndpointOrNull)
…
ip   = finalPin?.ip   ?: finalCandidate.profile.server
port = finalPin?.port ?: finalCandidate.profile.port
```

- خطِ لاگِ `mihomo.chain.healthy` حالا `pinned=<n>` هم دارد: از روی لاگ می‌شود
  شمرد که چند پا pin شده — یعنی «تانل واقعاً فعال است؟» بدونِ حدس.

## ۳) چرا نمایش مهم است (راهنمای بررسیِ خودت)

با تانلِ فعال و pin، آدرسی که در جزئیاتِ اتصال می‌بینی باید **همان IPِ pin‌شده**
باشد، نه دامنهٔ اشتراک. اگر دامنه را دیدی، pin نگرفته است.

## ۴) برچسبِ صداقتِ تست‌ها (سه لایه، صریح)

| لایه | چه چیزی را ثابت می‌کند | نتیجه |
| --- | --- | --- |
| `ConnectionChainTunnelTest.kt` (۸ تستِ JVM) | **خودِ Kotlin** روی YAMLِ تولیدی: pin روی `server`/`port`، «مسیرِ ۲ از خروجیِ مسیرِ ۱»، نگه‌داشتنِ آدرسِ بالادستِ کانفیگِ زنجیره‌ای، خطا در pinِ غیرقابلِ اعمال | سبز در CI (`Unit tests (JVM)`) |

## ۵) چیزهایی که هنوز نیست (همان‌طور که در beta104 گفته شد)

fronting روی رانتایمِ زنجیره، انتخابِ IP بر اساسِ پینگ، نقشِ صریحِ ProxyIP («مقصد»)،
و ۳-هُپیِ تست‌نشده روی گوشی.
