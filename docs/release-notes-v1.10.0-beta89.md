# Cat Client 1.10.0-beta89 (versionCode 156) — تست واقعی اتصال از مرورگر: هندشیک WebSocket روی مسیر تونل (پنل 6.58.0)

بتا۸۸ «زنده‌بودن لبه روی خط تو» را برای آی‌پی‌ها آورد؛ جای یک سؤال مانده بود: **آیا کانفیگ واقعاً از این دامنه وصل می‌شود؟** — نه فقط لبه، بلکه کل مسیر: TLS + مسیریابی کلودفلر + ارتقای WebSocket تا ورکر.

## چه چیزی اضافه شد (پنل 6.58.0)

### 🔌 «تست واقعی اتصال (دامنه‌ها)»
- برای هر دامنهٔ لیست، مرورگر یک **WebSocket واقعی به مسیر تونل (`/ws`)** باز می‌کند — دقیقاً همان دست‌دادنی که کانفیگ‌ها استفاده می‌کنند (ارتقای `isTunnelPath` ورکر، بدون نیاز به هیچ اعتباری در سطح اتصال).
- **باز شدن اتصال = کانفیگ روی خط تو واقعاً از این دامنه وصل می‌شود** (گواهی + لبه + مسیریابی به ورکر + ارتقا، همه با هم). خطا/بسته‌شدن/تایم‌اوت ۸ ثانیه = ✗.
- **آدرس خود پنل همیشه اول و به‌عنوان «مبنا» تست می‌شود** — اگر همان ✗ بخورد، مشکل از خط توست نه از دامنه‌ها.
- پین پورت TLS حفظ می‌شود (`dom:2053` ← `wss://dom:2053/ws`)؛ پورت‌های غیرTLS رد می‌شوند (هندشیک TLS روی پورت ساده جعلی است).

### چرا آی‌پی خام اینجا نیست (صادقانه)
مرورگر نمی‌تواند هدر `Host` را عوض کند — و اتصال به آی‌پی خام/دامنهٔ تمیزِ استخر دقیقاً با ترفند Host به ورکر می‌رسد. پس «تست واقعی» مرورگر فقط برای دامنه‌هایی معنادار است که به ورکر تو مسیریابی شده‌اند (آدرس ورکر، دامنهٔ سفارشی). دامنه‌ای که به ورکر وصل نباشد ✗ می‌خورد — که خودش عیب‌یابی مفیدی است («دامنه‌ام درست ست نشده»). به همین دلیل این تست **دکمهٔ حذف ندارد** و مشورتی است؛ حذف مرده‌ها همان «تست از شبکهٔ من» بتا۸۸ می‌ماند.

## تضمین دائمی
- `scripts/panels/ws-probe.test.mjs` (**تازه**، ۱۵ چک): با جا زدن کلاس `WebSocket` در جااس‌دام، رفتار «خط کاربر» شبیه‌سازی می‌شود: هندشیک `/ws` برای همهٔ هدف‌ها، باز شدن دامنه‌های سالم، ✗ برای دامنهٔ مرده، حفظ پین پورت در `wss://…:2053/ws`, آی‌پی خام هرگز پروب نمی‌شود، پورت ساده رد می‌شود، مبنای خود پنل همیشه هست، و این تست دکمهٔ حذف را فعال نمی‌کند. روی پنل قبلی (6.57.0) شکست می‌خورد.
- در `npm test` و هر دو ورک‌فلوی CI اجرا می‌شود.
