# Cat Client 1.10.0-beta79 (versionCode 146) — رفع بن‌بست «Invalid redirect_uri» در مسیر ساخت اکانت کلادفلر (پنل 6.52.0)

## مشکل چه بود؟
دکمهٔ «🔑 دریافت توکن کلودفلر» مستقیم به یک لینک **پارامتردار** می‌رفت:
`dash.cloudflare.com/profile/api-tokens?permissionGroupKeys=[…]&accountId=*&zoneId=all&name=Cat Panel`

وقتی کاربر **هنوز لاگین نیست**، صفحهٔ ورود/ثبت‌نام کلادفلر همین URL را به‌عنوان `redirect_uri` اعتبارسنجی می‌کند و ردش می‌کند → پیام **«Invalid redirect_uri - does not match configured values»** دقیقاً همان‌جایی که کاربر می‌خواهد اکانت بسازد؛ جریان همان‌جا می‌مرد.

## راه‌حل (ترتیب درست)
مسیر اکانت فقط با لینک‌های **بدون پارامتر** کار می‌کند (هیچ‌چیز برای اعتبارسنجی وجود ندارد):
1. **🆕 ساخت اکانت رایگان کلادفلر** → `dash.cloudflare.com/sign-up`
2. **🔑 ورود به اکانت کلادفلر** → `dash.cloudflare.com/login`
3. **📄 صفحهٔ توکن (دسترسی‌ها از قبل انتخاب‌شده)** → همان لینک قالب — این بار چون نشست (session) وجود دارد، **مستقیم روی داشبورد** باز می‌شود و اصلاً ریدایرکتی رخ نمی‌دهد
4. **🧾 صفحهٔ توکن‌ها بدون پیش‌انتخاب** → `dash.cloudflare.com/profile/api-tokens` (جایگزین همیشگی)

این چهار مسیر هم به‌صورت **دو دکمهٔ جدا روی کارت پنل** (ساخت اکانت / ورود، با متن راهنما) و هم داخل یک **دیالوگ راهنما** هنگام زدن دکمهٔ توکن ارائه می‌شوند. متن اشتراک لینک «Deploy to Cloudflare» هم همان هشدار را گرفت.

## تضمین دائمی
- تست JVM جدید `CloudflareAccountLinksTest` (۳ بند ← در `./gradlew :app:testDebugUnitTest` در CI اجرا می‌شود):
  - لینک‌های اکانت **باید** بدون پارامتر و روی `dash.cloudflare.com` بمانند (اگر کسی query اضافه کند، تست fail می‌شود),
  - لینک قالب توکن **باید** پارامتردار بماند و همان دسترسی‌های پیش‌انتخاب‌شده را داشته باشد,
  - شکل لینک دکمهٔ دیپلوی هم قفل شد.
- `CloudflareAccountLinks` تنها منبع این URLها است؛ UI مستقیم URL نمی‌سازد.
