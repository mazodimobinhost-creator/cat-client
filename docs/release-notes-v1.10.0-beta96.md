# Cat Client 1.10.0-beta96 (versionCode 163) — آیکونِ خرابِ SVG رفع شد، و تستِ مرورگر گیتِ دائمی شد

این نسخه دو چیزِ محصولی دارد؛ هیچ‌کدام مربوط به «مسیرِ کلودفلر» نیست، چون آن یکی همچنان
به وضعیتِ حساب گره خورده است.

## ۱) باگِ واقعیِ SVG: مسیرِ آیکونِ «ابزار» هشت‌پارامتری بود

تستِ خودکارِ مرورگر (Chromium روی موتورِ واقعیِ workerd) این را از دلِ کنسول بیرون کشید:

```
Error: <path> attribute d: Expected number, "…12 2.12 0 01-3-3l6.91-6.91a6 6 0…"
```

قوسِ SVG هفت پارامتر دارد (`rx ry rotation large-arc sweep x y`); مسیرِ آیکون یک `2.12`
اضافه داشت. با پارسرِ مستقل هم تأیید شد: رشتهٔ قبلی **استثنا می‌دهد**، اصلاح‌شده ۵ قوسِ
سالم می‌سازد. یعنی مرورگر آن قوس را دور می‌ریخت و آیکون ناقص رندر می‌شد.

منبع (`catclient.worker.js`) اصلاح شد و **هر چهار آرتیفکت** با ابزارهای خودِ ریپو بازتولید
شدند: `catpanel.min.js`، `catpanel.obf.js` (همان که اپ آپلود می‌کند)، `catpanel.stealth.js`
و `cat-panel.html`. نسخهٔ پنل همان **۶.۶۷.۰** می‌ماند — این یک اصلاحِ رندر است، نه تغییرِ قابلیت.

## ۲) تستِ مرورگرِ خودکار، گیتِ دائمی شد

`.github/workflows/ui-e2e.yml` پنل را روی موتورِ واقعیِ کلودفلر (workerd) بالا می‌آورد، با
Chromium واقعی از **فرمِ ورود** لاگین می‌کند، نشست را وریفای می‌کند، **هر ۱۰ بخشِ ناوبری**
را با کلیک چک می‌کند (شاملِ باز کردنِ منوی همبرگری، همان‌طور که کاربر موبایل می‌کند) و
مسیرهای عجیب را می‌سنجد — ۲۶ بررسی، بدونِ هیچ سکرتی. حالا روی `main`، `arena/*` و
**pull request**ها با هر تغییرِ کدِ پنل یا ابزارش خودکار اجرا می‌شود و اگر چیزی بشکند،
**قرمز می‌شود** (خروجی و اسکرین‌شات هم آپلود می‌شوند).

چیزهایی که در همین پاس تأیید شدند: ورود، ۴۰۱ِ ناشناس، `/api/diag`، `/api/backup` با رازِ
ماسک‌شده، لینکِ ساب روی هاستِ درست، قفل‌بودنِ نشستِ تازه — و **صفر خطای کنسولی**.

## ۳) به‌همراهِ نسخه‌های قبل (beta94/95)

- انتظارِ فعال‌شدنِ مسیر: **۱۹×۵۰۰۰ms = ۹۰ ثانیه** و حالتِ میانیِ `PENDING` (پاسخِ ۴۰۴ خودِ
  کلودفلر با بدنهٔ HTML) با دیالوگِ «⏳ پنل هنوز در حال فعال‌شدن است» + «بررسی دوباره».
- متنِ حالتِ میانی بر اساسِ اندازه‌گیریِ واقعیِ حساب به‌روز شد.

## ۴) محدودیتِ صادقانه

- آپلود/دیپلوی روی کلودفلر تا وقتی حساب در حالتِ `9109 — User was deactivated` است کار
  نمی‌کند؛ خطای خامِ API به کاربر نشان داده می‌شود.
- کدِ Kotlin در محیطِ ساختِ این گفتگو کامپایل نمی‌شود؛ تأییدِ نهایی همان بیلدِ همین انتشار است.
