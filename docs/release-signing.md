# Cat Client release signing and in-app updates

Android only accepts an in-place APK update when the new APK has the same package name **and the same signing certificate** as the installed APK. Cat Client's in-app updater also checks the certificate before opening the Android installer.

Configure one long-lived release keystore in the repository's GitHub Actions secrets. Do not commit the keystore or its passwords.

```bash
keytool -genkeypair -v \
  -keystore catclient-release.jks \
  -alias catclient \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -storepass 'CHOOSE_A_LONG_PASSWORD' \
  -keypass 'CHOOSE_A_LONG_PASSWORD' \
  -dname 'CN=Cat Client'

base64 -w 0 catclient-release.jks > catclient-release.jks.b64
```

Add these repository secrets under **Settings → Secrets and variables → Actions**:

- `CATCLIENT_RELEASE_KEYSTORE_B64`: the one-line contents of `catclient-release.jks.b64`
- `CATCLIENT_RELEASE_STORE_PASSWORD`: the keystore password
- `CATCLIENT_RELEASE_KEY_ALIAS`: `catclient`
- `CATCLIENT_RELEASE_KEY_PASSWORD`: the key password

The workflow validates the APK package, version, ABI variants, signature, alignment and SHA-256 checksums before uploading a release. The app then selects the matching ABI APK, verifies the checksum and signing certificate, and opens the Android package installer.

The fallback key generated by CI is intentionally temporary and is not upgrade-safe. It is useful for smoke-test APKs only. A device that already has an APK signed with that fallback key must be migrated once by uninstalling it before installing the first stable-key release; future stable-key releases upgrade in place.
