# Cat Client v1.10.0-beta103 (versionCode 170) — پنل 6.67.1: چهرهٔ دومِ ۱۱۰۱

این نسخه یک حفرهٔ واقعی در گاردِ ۱۱۰۱ را می‌بندد و پنلِ همراه را به **6.67.1** می‌برد.

## ۱) ۱۱۰۱ دو چهره دارد؛ ما فقط یکی را می‌گرفتیم

مستنداتِ کلودفلر ۱۱۰۱ را برای دو حالت می‌دهد:

1. **استثنای گرفته‌نشده** — این را گاردِ سراسری می‌گیرد و `panel_crash` می‌دهد ✔
2. **«The script will never generate a response»** — هندلر تمام می‌شود ولی **هیچ
   Response‌ای برنمی‌گرداند**. این یکی **استثنا نیست**، پس `try/catch` اصلاً نمی‌بیندش:
   catch فقط throw را می‌گیرد، نه `undefined` را.

یعنی اگر یک شاخهٔ مسیر در کدِ ۷۸۰۰ خطی جا می‌افتاد و `return` نداشت، کاربر صفحهٔ خامِ
۱۱۰۱ می‌گرفت و **هیچ گزارشی هم تولید نمی‌شد** — همان موردی که تشخیصش غیرممکن است.

**اصلاح:** حالا خروجیِ هندلر بررسی می‌شود:

```js
const res = await handleRequest(request, env, ctx);
if (!(res instanceof Response)) {
  throw new Error('handler returned ' + (res === null ? 'null' : typeof res) +
                  ' instead of a Response — a route branch fell through');
}
```

همین یک بلوک، آن حالت را به **همان مسیرِ کرشِ موجود** می‌سپارد: مالک JSONِ
`panel_crash` می‌گیرد که `at:`‌اش **نامِ همان مسیرِ خراب** را می‌گوید، غریبه همان
پاسخِ خنثی را می‌گیرد، و در `/api/diag` با `recentErrors` ثبت می‌شود.

سه تستِ تازه در `scripts/panels/cat-panel.test.mjs` از این محافظ نگهبانی می‌کنند:
وجودش، اجرا شدنش **قبل از** `return res`، و اینکه `throw`‌اش **داخلِ** بلوکِ try است
(وگرنه به مسیرِ کرش نمی‌رسد).

## ۳) جمع‌بندیِ «آیا rule ای در کلودفلر این را درست می‌کند؟»

خیر — و دلیلش ساختاری است: WAF/Rate limiting/Redirect روی **درخواست** ارزیابی
می‌شوند، نه روی پاسخ؛ و ۱۱۰۱ یعنی کد یا اجرا نشده یا چیزی برنگردانده. هیچ rule ای
نمی‌تواند ماژولی که لود نشده را «درست» کند. سه چیزِ واقعی که به کار می‌آید:

1. **Rollback** (Deployments → ⋯ → Rollback) — فوری به نسخهٔ سالم قبل برمی‌گردد.
2. **نسخه‌بندیِ دیپلوی / Workers Builds** — تا به rollback نیاز نشود.
3. **ورکرِ جلویی + Service Binding** (شیلد) — تنها چیزی که شبیهِ «قانون» است: یک
   ورکرِ کوچکِ همیشه‌سالم روی دامنه می‌نشیند و پنل را از طریقِ service binding
   صدا می‌زند؛ اگر پنل استثنا داد، خطا در fetchِ caller **پرتاب می‌شود** (رفتارِ
   service bindings مثل dynamic dispatch) و ورکرِ جلویی به‌جای صفحهٔ ۱۱۰۱ یک پاسخِ
   تمیز می‌دهد.

شرحِ کاملِ هر سه + دو نوع rate limit + چیزهایی که *راه‌حل نیستند*:
`docs/panel-1101-cloudflare-rules.md`.
