# Cat Client v1.10.0-beta104 (versionCode 171) — بخشِ تانل: IP در زنجیره

این نسخه همان چیزی است که خواستی: **IP ایران** و **IP خارجیِ کلودفلر (که از
ProxyIP می‌آید)** حالا می‌توانند وارد یک تونل شوند — به‌شکلی که با ساختارِ واقعی
میهومو جور باشد. پنل همراه هم همان **6.67.1** beta103 است (تغییری ندارد).

## ۱) چرا «IP = یک هُپ» غلط بود و چه چیزی درست است

یک هُپ در این اپ یک **کانفیگ** است: UUID، SNI، ترنسپورت، پروتکل. یک IP خالی هیچ‌کدام
را ندارد، پس نمی‌تواند خودش هُپ باشد. ولی **آدرسی که آن کانفیگ از آن دیال می‌شود**
می‌تواند عوض شود — و این دقیقاً همان چیزی است که «تانل‌کردنِ IP» یعنی. پس هر مسیر
یک فیلد تازه گرفت:

```
IP مسیر: 104.16.0.1        ← یا خالی (آدرس خودِ کانفیگ)
```

و **فقط اولین پروکسیِ آن مسیر** پچ می‌شود؛ چون فقط همان پا از بیرونِ هُپ دیال
می‌شود: دستگاه → اولین پروکسیِ مسیرِ ۱، و اولین پروکسیِ هر مسیرِ بعدی از راهِ مسیرِ
قبلی. اگر بقیهٔ پروکسی‌ها هم پچ می‌شدند، آدرسی که یک کانفیگ برای رسیدن به بالادستِ
خودش لازم دارد از بین می‌رفت.

## ۲) چه چیزی در اپ عوض شد

- **اسلاتِ ورودی زنده شد.** تا قبل، انبارِ تنظیمات عمداً `before = off` می‌کرد و
  همان را هم نمی‌خواند؛ یعنی «ورودی» هرگز نمی‌توانست وجود داشته باشد. حالا هر سه
  ردیف — **ورودی / پایه / بعد** — ذخیره، خوانده و در صفحه نشان داده می‌شوند.
- **چیپِ «IP مسیر» روی هر ردیف** (۴۴px، RTL): زدنش دیالوگ را باز می‌کند؛ IP را
  دستی بنویس یا از مسیرهای fronting بردار، یا با «پاک‌کردن» به آدرسِ خودِ کانفیگ
  برگرد. `IP` یا `IP:port` (IPv6 با براکت) پذیرفته می‌شود و مقدارِ نامعتبر همان‌جا
  رد می‌شود.
- **دکمهٔ «استفاده به‌عنوان entry» در اسکنرِ ProxyIP:** اگر زنجیره فعال باشد،
  زنجیره **دست‌نخورده می‌ماند** و IP روی **اولین مسیرِ پیکربندی‌شده** pin می‌شود؛
  توست می‌گوید کدام مسیر. اگر زنجیره خاموش باشد، همان رفتارِ fronting قبلی است.
- **انتخابِ دوبارهٔ کانفیگ برای یک مسیر، IP آن مسیر را پاک نمی‌کند** (IP به پا
  مربوط است، نه به کانفیگ).
- **ضدِ خرابی:** IP بی‌شکل هنگام normalize حذف می‌شود (نه اینکه وسطِ اتصال throw
  کند) و اگر کانفیگی فیلدِ `server:` قابلِ پچ نداشته باشد، خطا **بلند** داده
  می‌شود تا بی‌صدا IPِ تو نادیده گرفته نشود.

## ۳) تست و برچسبِ صداقت

- `scripts/panels/chain-tunnel.test.mjs` (۷ تست) + `npm test` سبز (۵۷ تست) —
  این‌ها **source-level** هستند: شکلِ سیم‌کشیِ Kotlin را قفل می‌کنند، نه رفتار را.
- `app/src/test/java/com/cat/client/ConnectionChainTunnelTest.kt` (۸ تستِ **JVM**،
  همان Kotlin روی همان ماشین، در CI اجرا می‌شوند) — این‌ها **رفتارِ واقعیِ** استخراج
  YAML را می‌سنجند: pin شدنِ `server`/`port`، اینکه «مسیرِ دوم از خروجیِ مسیرِ اول
  دیال می‌کند»، اینکه یک کانفیگِ زنجیره‌ای **آدرسِ بالادستِ خودش** را از دست نمی‌دهد،
  و خطا در جایی که pin قابلِ اعمال نیست. برچسب: **JVM/CI** — نه «تست‌شده روی گوشی».
- روی حسابِ کلودفلر چیزی عوض نشده؛ پنل همان 6.67.1 است.

## ۴) چیزهایی که هنوز نیست

1. fronting (لیستِ IP) روی رانتایمِ **زنجیره** اعمال نمی‌شود — به همین دلیل IP از
   راهِ pin وارد می‌شود. اگر بخواهی، کارِ بعدی همین است.
2. انتخابِ IP بر اساسِ پینگ/کشور داخلِ همان دیالوگ.
3. نقشِ صریحِ ProxyIP («مقصد») در همین صفحه.
