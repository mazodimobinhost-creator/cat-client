# «Error 1101» به زبان ساده — چه هست، چه نیست، و چه باید کرد

سندی کوتاه و صادقانه برای مالکِ همین پنل. نسخهٔ انگلیسیِ مفصل در README (بخش
«⚠️ Error 1101») و قواعدِ رسمیِ کلادفلر در `docs/panel-1101-cloudflare-rules.md` است.

## ۱) تعریفِ مستند

کلادفلر در مستنداتِ خودش **1101 را این‌طور تعریف می‌کند: «Worker threw a JavaScript exception»**
— یعنی کدِ ورکر اجرا شد، یک استثنا پرتاب شد و هیچ‌کس آن را نگرفت؛ پس لبه (edge) صفحهٔ خطای
خودش را نشان می‌دهد. این تعریف رسمی است و همان چیزی است که روی آن حساب می‌کنیم.

> نکتهٔ مهم و صادقانه: داستانِ «کلادفلر سورسِ ورکر را برای امضاهای vless/trojan اسکن می‌کند و
> ورکر را با 1101 خاموش می‌کند» **تأییدنشده** است — فقط گزارش‌های اجتماعی از نوامبر ۲۰۲۴ است و
> هیچ بیانیهٔ کلادفلر پشتش نیست. اگر سوسپند بعد از ریپورتِ ابیوز اتفاق بیفتد، نتیجهٔ ظاهری‌اش
> 1101 است؛ ولی این «ظاهر یکسان» دلیل بر آن مکانیزم نیست.

## ۲) ۱۱۰۱ یک معنا ندارد — چهار چهره دارد

| چه اتفاقی افتاده | چه کسی می‌گیردش | چه می‌بینی |
|---|---|---|
| خطا **داخل `fetch()`** (همین درخواست) | `try/catch` بیرونیِ پنل | JSON گزارش (`panel_crash`) برای مالک / JSON خنثی برای غریبه — **هرگز** صفحهٔ 1101 |
| فایل **هرگز evaluate نشد**: خطای سینتکس، پیستِ ناقص، پرتاب در scope سراسری | هیچ‌کس — ماژول لود نشده | **1101 روی همهٔ مسیرها**، تا وقتی دوباره دیپلوی کنی |
| هندلر تمام شد ولی **`Response` برنگرداند** (شاخهٔ route افتاده بود) | `instanceof Response` در wrapper (از 6.67.1) | قبل از 6.67.1: 1101 بدون هیچ گزارشی؛ از 6.67.1: مسیر عادیِ crash و فیلدِ `at:` مسیر را می‌گوید |
| **کشتِ مهلکِ رانتایم**: کمبود حافظه، یا کشته‌شدن وسط درخواست | هیچ‌کس — isolate می‌میرد | صفحهٔ 1101 (برای CPU: **1102**) |

پس اولین سؤال همیشه این است: **فایل لود شد یا نه؟** — و این با «چه جوابی می‌دهد» معلوم می‌شود،
نه با خودِ صفحهٔ خطا.

## ۳) تشخیصِ قطعی (بدونِ ترمینال)

**تستِ سه‌نقطه‌ای** (در اپ: «تستِ سه‌نقطه‌ای پنل (1101)») سه URL را می‌پرسد:

1. `/health` → `{"ok":true}` یعنی ورکر پاسخ می‌دهد؛
2. `/api/version` → **JSON** یعنی ماژول لود و اجرا شده (پس خطا per-request است و خودِ پنل گزارشش
   می‌کند) — هر چیزِ دیگری (صفحهٔ 1101 یا HTML) یعنی کد هرگز اجرا نشده؛
3. `/api/selfcheck?throw=1` → عمداً داخل ورکر پرتاب می‌کند؛ اگر `error:"panel_crash"` و `stack`
   برگشت، یعنی گاردِ 1101 کار می‌کند. غریبه قبل از پرتاب `401` می‌گیرد.

از خط فرمان همان کار:

```bash
curl -s -H "x-cat-key: <رمز پنل یا UUID>" https://<worker>/api/version
curl -s -H "x-cat-key: <رمز پنل یا UUID>" "https://<worker>/api/selfcheck?throw=1" | head -c 400
```

## ۴) اگر الان 1101 می‌بینی، بهترتیب

1. **تستِ سه‌نقطه‌ای** را بزن تا بفهمی «لود نشده» است یا «per-request».
2. اگر **لود نشده** (کد اجرا نشد):
   - در داشبورد: Workers & Pages → ورکرت → **Deployments** → نسخهٔ قبلی → **Rollback**
     (سریع‌ترین بازگشت به کار).
   - فایل را از نو و کامل آپلود کن؛ نامِ ورکر دقیقاً همان قبلی باشد. فایلِ معتبر را از سه چیز
     بشناس: خطِ اولِ مارکر (`/* CAT_PANEL_VERSION = '...' */`)، سایز بایت‌ها، و
     `node --check` روی همان فایل. ادیتورِ مرورگر خطوط بلند را می‌شکند، پس «دو خط به‌نظر می‌رسد»
     هیچ معنایی ندارد — تعداد بایت مهم است.
   - **بایندینگِ `CAT_KV` را حفظ کن**: دیپلوی در کلادفلر «اعلامی» است؛ اگر در فایل نباشد،
     وریبل/بایندینگی که فقط در داشبورد بود حذف می‌شود.
3. اگر **per-request** (JSON برگشت): `/api/diag` (مالک) یا `PANEL_DIAG=1` را ببین؛ گزارش دقیقاً
   `at:` با مسیرِ خطادار، `message` و `stack` دارد. لاگ‌های داشبورد (Logs/Observability یا
   `wrangler tail`) هم همان استثنا را نشان می‌دهند.
4. فقط اگر روی **نامِ تازه یا اکانتِ تازه** هم تکرار شد، فرضِ مسدودشدن معنا پیدا می‌کند: بکاپ بگیر
   (ابزارها)، ورکر را حذف کن، از نو دیپلوی کن، بکاپ را برگردان.

## ۵) آنچه کدِ ما از قبل پوشش می‌دهد — و آنچه هرگز نمی‌تواند

**پوشش دارد:** هر خطای داخل `fetch()` (حتی پرتابِ رشته/null/آبجکتِ خراب)، خطای هندلری که
`Response` برنگردانده (از 6.67.1)، و پاسخِ خنثی برای غریبه‌ها (جزئیات فقط برای مالک یا با
`PANEL_DIAG=1`).

**هرگز نمی‌تواند پوشش بدهد** (چون هیچ کدی از ما اجرا نمی‌شود): خطای سینتکس/لود، پیستِ ناقص،
پرتاب در scope سراسری، کشتِ مهلکِ رانتایم، و دیپلویی که API رد کرده. برای همین سه محافظِ
دیگر وجود دارد: گیتِ `pasteScriptIsSane()` در اپ، آپلودر با `Content-Length` دقیق (تا نوشتنِ
ناقص، ماژولِ نصفه ذخیره نکند)، و بازپخشِ بیلد روی موتورِ واقعی Workers (workerd) در CI.
