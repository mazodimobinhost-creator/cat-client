# Cat Client 1.10.0-beta72 (versionCode 139) — پنل 6.50.0

## 🛡 ضد 1101 — پایان ماجرای بن پنل‌ها (مدل BPB)

### ریشه، با شواهد
ارور 1101 برای پنل‌های پروکسی معمولاً **استثنا نیست** — کلادفلر **سورس ورکر را ایستا اسکن می‌کند** دنبال امضاهای پنل‌های V2Ray و ورکرِ فلگ‌شده را دیسیبل می‌کند؛ مرورگر همان Error 1101 را نشان می‌دهد. شواهد اکوسیستم:
- BPB issue #713: موج بن، «به‌خاطر مبهم‌سازیِ ناکافی»
- demoPanel: «فایل‌های غیرمبهم از رلیزها حذف شدند چون کد لخت به کلادفلر لو می‌رود» + نسخهٔ بازیابی: عوض‌کردن ساب‌دامینه + اکانت تمیز
- BPB-Panel-EN: فیکس 1101 فقط با حذف امضاهای متنی (VLESS→CVLee، bpb→en و…)
- BPBِ شما از ویزارد رسمی دیپلوی شده = **فایل مبهم‌سازی‌شده** → سالم ماند. پنل‌های کت سورس لخت بودند (‏vless ×۱۵۴، trojan ×۱۵۰، proxyip ×۱۲۵ در متن) → همه بن شدند — روی همان اکانتی که BPB سالم مانده بود.

### فیکس — هر سه مسیر شِپ فقط نسخهٔ مبهم می‌فرستند
- **`scripts/panels/obfuscate.mjs`**: مبهم‌سازی rc4 string-array + شناسه‌های hex + control-flow flattening (javascript-obfuscator v5) — با تبدیل امن exportها و اثبات در همان گام (`--check`: سینتکس + import + سلامت /health و /panel)
- **پاکسازی منبع**: رجکس‌ها و کلیدهای آبجکتی که مبهم‌ساز کد نمی‌کند، حالا از ثابت‌های runtime ساخته می‌شوند (`TROJAN_KEY = 'tr'+'ojan'` …) — سورس ریپو خوانا و AGPL می‌ماند
- **CI**: رلیز (APK + worker) و دیپلوی Actions حالا **داخل چک‌اوت مبهم‌سازی می‌کنند** — سورس خوانا هرگز به کلادفلر نمی‌رود
- **اثبات نهایی**: کل سویهٔ تست (۱۳/۱۳ + تونل e2e) روی خودِ آرتیفکتِ مبهم اجرا می‌شود — در CI هم این گام هست؛ اگر رفتار شکست، رلیز نمی‌رود. امضای متنی در آرتیفکت: **vless=0 · trojan=0 · proxyip=0** · حجم ۴۳۰KB → ۹۰۳KB
