# Cat Client 1.10.0-beta92 (versionCode 159) — رفع ساب خالی و خطای ذخیرهٔ کاربر

## ۱) وقتی فهرست IP خالی است، ساب دیگر بی‌دلیل خالی نمی‌ماند
اگر فهرست IP اختصاصی پنل خالی باشد، آدرس‌های محیطی هم وجود نداشته باشند و هر دو گزینهٔ «آدرس‌های پیش‌فرض» و «دامنهٔ ورکر» خاموش شده باشند، ساخت ساب برای همان درخواست موقتاً به آدرس‌های پیش‌فرض پنل و دامنهٔ خود ورکر برمی‌گردد. این fallback در KV ذخیره نمی‌شود و تنظیمات انتخابی مالک را تغییر نمی‌دهد؛ IPهایی که مالک اضافه کند همچنان جلوتر می‌آیند.

این تغییر تضمین نمی‌کند که هر IP پیش‌فرض روی هر خط کار کند. مقصد هر ساب باید از خط و کلاینت خود کاربر تست شود.

فیدهای عمومی مسیر جداگانه دارند: گزینهٔ clean-IP با نام «افزودن خودکار IPهای مخزن به ساب» به‌صورت پیش‌فرض خاموش است؛ وقتی مالک آن را روشن کند، IPهای سالمِ کش‌شده پس از IPهای خود مالک به اشتراک اضافه می‌شوند، اما به فهرست ذخیره‌شدهٔ IPهای مالک کپی نمی‌شوند. فید ProxyIP هم استخر جداگانه‌ای است و کانفیگ رله می‌سازد، نه اینکه IP تمیز معمولی را به لیست اتصال تبدیل کند. این تغییر هیچ‌کدام از تنظیمات اپت‌این را بی‌اجازه روشن نمی‌کند.

## ۲) خطای واقعیِ پیش‌نمایش ساب نمایش داده می‌شود
قبلاً هر پاسخ HTTP ناموفق یا بدنهٔ غیرعادی به شکل «هیچ IP تمیزی در پنل نیست» نشان داده می‌شد. حالا پیش‌نمایش خطای HTTP/شبکه، پاسخ خالی یا پاسخ غیرساب را جدا گزارش می‌کند. بدنهٔ خام پاسخ در گزارش UI نمایش داده نمی‌شود.

## ۳) خطای ساخت کاربر دیگر مبهم نیست
اگر ساخت یا ویرایش کاربر از سمت پنل رد شود، پیام شامل کد HTTP و علت پاسخ است، نه فقط «error». شناسه‌های UUID و URLها پیش از نمایش در پیام خطا حذف/ماسک می‌شوند. اگر API ذخیره را موفق اعلام کند اما KV متصل نباشد، هشدار جداگانهٔ ذخیره‌نشدن همچنان نمایش داده می‌شود. همچنین اگر POST ساخت کاربر موفق باشد اما بارگذاری دوبارهٔ فهرست شکست بخورد، پیام می‌گوید کاربر ذخیره شده و خطای تازه‌سازی را جدا نشان می‌دهد؛ دیگر کاربر را به تکرار ناخواستهٔ ساخت هدایت نمی‌کند.

## نسخهٔ پنل
- نسخهٔ Worker داخل بسته: **6.60.0**.
- اگر پنل زنده‌ات هنوز نسخهٔ قبلی را نشان می‌دهد، به‌روزرسانی Worker را از بخش دیپلوی‌های Cat Client یا روش استقرار خودت اجرا کن. انتشار اپ به‌تنهایی Worker مستقرشده را خودکار عوض نمی‌کند.

## تست‌ها
- تست worker برای سابِ فهرست خالی، استفاده از آدرس‌های پیش‌فرض و عدم ذخیرهٔ fallback؛ مقادیر فرم همان اسکرین‌شات نیز باید با HTTP 201 پذیرفته شوند.
- تست DOM برای خطای واقعی ساخت کاربر، شکست تازه‌سازی پس از ذخیرهٔ موفق، خطای HTTP/ساب خالی، شمارش پیش‌نمایش موفق و عدم نمایش بدنهٔ خام پاسخ.
- `npm test` و CI اندروید/پنل.
