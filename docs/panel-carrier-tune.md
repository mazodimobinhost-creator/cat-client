# پنل → اپ: پیشنهاد پریست فرگمنت به تفکیک اپراتور (۶.۶۷.۲ / beta106)

این سند یک قابلیتِ واقعی را توصیف می‌کند که از مطالعهٔ `UAC-SNI-Spoofer` بیرون آمد، ولی با کدِ خودمان
نوشته شده (هیچ خطی از آن مخازن برداشته نشده؛ ممیزیِ مجوز در `docs/third-party-study-uac-sni-spoofer.md`).

## چرا این قابلیت

`UAC` روی اندروید برای هر اپراتور یک پروفایلِ فرگمنت جدا دارد (`mci` با `fake SNI` و fingerprint
`unsafe`، ایرانسل با `finalmaskMaxSplit=100`). ما همان جنس ابزار را داریم ولی پشتِ `ByeDPI`
(CIADPI) و با argsی خودمان — یعنی «کدام برشِ ClientHello» را از قبل داریم، اما:

* اپ مجبور بود حدس بزند کاربر روی کدام اپراتور است (چیپ‌های دستی)، و
* روزی که اپراتور DPI را عوض کند، تنها راهِ اصلاحش انتشارِ APK جدید بود.

## چه چیزی اضافه شد

**سمت اپ**

| قطعه | کار |
|---|---|
| `MobileCarrier.kt` | تشخیصِ اپراتور از `TelephonyManager.networkOperator` (و در نبودش `simOperator`) — MCC ۴۳۲؛ MCI/ایرانسل/رایتل/مخابرات، بقیه `other`، نامعلوم `unknown`. `rawOperatorCode()` برای لاگ. بدونِ هیچ مجوزِ اضافه (کدِ اپراتور، نه هویتِ مشترک). |
| `PanelTune.kt` | خواندنِ جدولِ مالک از پنل + کشِ روی‌دیسک + پارسِ whitelist-محور. |
| `DpiFragmentPreset.forCarrier/resolve` | نردبانِ تصمیم: انتخابِ دستی → پیشنهادِ پنل → جدولِ داخلیِ اپراتور → `default`. `auto` یعنی «خودت تصمیم بگیر». |
| `MainActivity` | خطِ «اپراتور: … → پریست: …» بالای چیپ‌ها + چیپِ **خودکار** + چیپِ **PattN** (که در enum بود ولی هیچ‌وقت نمایش داده نمی‌شد) + یک receiver برای تغییرِ اپراتور/شبکه. |
| `CatClientVpnService` | در لحظهٔ اتصال `resolve(...)` صدا زده می‌شود و نتیجه در `dpiBypass.preset` لاگ می‌شود. |

**سمت پنل**

* `GET /api/tune` (عمومی — هیچ رازی در پاسخ نیست) → JSON برای صفحهٔ پنل.
* `GET /api/tune?format=text` → همان جدول به‌صورت متنِ ساده و با خطِ جادوییِ `cat-panel-tune v1`.
* `PUT /api/tune` (فقط مالک) → `{tune:{mci:'pattn', …}}`، با `sanitizeTune()` روی ورودی و خروجی.
* کارتِ «پیشنهاد پریست فرگمنت برای اپ» در تب تنظیمات، ذیلِ کارتِ فرگمنت — چهار انتخاب برای چهار اپراتور.

## چرا متنِ ساده و نه JSON

اپ روی `org.json` حساب می‌کند و آن در تست‌های JVM یک stub است؛ یعنی مسیرِ JSON عملاً
تست‌ناپذیر می‌شد یا یک وابستگیِ جدید لازم داشت. متنِ ساده سه چیز را هم‌زمان می‌دهد:

1. صفر وابستگی و صفر پارسر در runtime،
2. یک خطِ نسخه‌دار (`cat-panel-tune v1`) که «این واقعاً جدولِ ماست» را **قابلِ‌اثبات** می‌کند —
   صفحهٔ لاگین، ریدایرکتِ کپتیو‌پورتال یا ورکرِ قدیمی نمی‌تواند جایِ تنظیمات جا بزند،
3. ورودیِ قابلِ‌تست برای یک تستِ خالصِ JVM.

## رفتار در حالت‌های خراب (طراحی‌شده، نه اتفاقی)

| وضعیت | نتیجه |
|---|---|
| پنل در دسترس نیست / آفلاین | کشِ قبلی می‌ماند؛ اگر کش هم نباشد جدولِ داخلیِ اپراتور اعمال می‌شود. |
| پنل ورکرِ قدیمی است (`/api/tune` ندارد) | ۴۰۴ → بدونِ کش؛ رفتارِ قبلی دست‌نخورده. |
| پاسخ HTML (صفحهٔ لاگین/ورکرِ دیگر) | `content-type` متن نیست یا خطِ جادویی نیست → رد می‌شود. |
| مقدارِ ناشناخته (اپراتور یا پریست) | در پنل و در اپ هر دو حذف می‌شود؛ هرگز به مرحلهٔ اتصال نمی‌رسد. |
| کاربر انتخابِ دستی کرده | پیشنهادِ پنل نادیده گرفته می‌شود (تصمیمِ کاربر بالاتر از مالکِ پنل است). |

## چطور تست شده (برچسبِ صادق)

* `scripts/panels/tune.test.mjs` — **۹ تستِ اجراشده** روی ورکرِ واقعی با KVِ جعلی: قالبِ متن،
  برابریِ متن و JSON، ۴۰۱ برای نویسندهٔ ناشناس، whitelist روی مقدارِ خراب، و انطباقِ شناسه‌ها با
  enumِ کاتلین.
* `app/src/test/java/com/cat/client/PanelTuneTest.kt` — **۸ تستِ JVM** روی پارسر و نردبانِ تصمیم و
  نگاشتِ MCC/MNC. (در این سندباکس JDK نیست؛ اجرای واقعی در CI است.)
* `npm test` کامل + کامپایلِ کاتلین در CI.
* **تأییدنشده روی گوشی**: تصمیمِ نهایی «کدام پریست روی این خط جواب می‌دهد» همان چیزی است که
  فقط با تستِ میدانی معلوم می‌شود؛ این قابلیت آن تصمیم را **قابلِ تغییر بدونِ انتشار APK** می‌کند،
  ولی صحتش را تضمین نمی‌کند.

## آنچه از این ایدهٔ UAC عمداً پیاده نشد

* `finalmask`/`xray` (ما `mihomo` داریم؛ جست‌وجو در مخزنِ آن: صفر نتیجه) — تصمیم در سندِ مطالعه.
* جعلِ SNI به‌صورت «تزریقِ بستهٔ سطحِ ویندوز» (نیازمندِ WinDivert و ادمین) — روی اندروید معادلِ
  امن و بدون root ندارد.
